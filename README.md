# Інтернет-магазин спортивного харчування  

Веб-платформа для продажу спортивного харчування, добавок та суміжних товарів із розширеним функціоналом каталогу, кошика, системи замовлень та особистих кабінетів користувачів.

---

## Технологічний стек

* **Backend:** Node.js / TypeScript, Express
* **Frontend:** React, Vite
* **Якість коду та Git Hooks:** ESLint, Prettier, Husky
* **Тестування:** Jest / Vitest

## Регламент командної роботи з Git та гілками

У проєкті використовується чіткий командний процес розробки через окремі гілки та обов'язкове злиття за допомогою Pull Requests:

1. **Стратегія гілок:**
   * `main` — основна стабільна гілка коду.
   * `chore/` — гілки для початкового налаштування інфраструктури, документації та репозиторію.
   * `feature/` — персональні робочі гілки для розробки функціональних модулів.
   * `tools` — Налаштування хуків, лінтерів тощо.
2. **Автоматичні перевірки (Husky):**
   * Перед кожним коммітом (`pre-commit`) автоматично виконується перевірка коду лінтером (ESLint) та форматування (Prettier).
   * Перед пушем (`pre-push`) запускається перевірка тестами.
3. **Процес злиття:**
   * Прямі коміти у головну гілку `main` заборонені. Усі зміни інтегруються виключно через Pull Request після перевірки іншими членами команди.

## Структура проєкту

Проєкт організовано із чітким розподілом на клієнтську та серверну частини:

```text
SDLC/
├── .husky/                  # Git-хуки для автоматичних перевірок перед коммітом/пушем
│   ├── pre-commit
│   └── pre-push
├── backend/                 # Серверна частина додатка (Node.js / TypeScript)
│   ├── src/
│   │   ├── adapters/        # Зовнішні адаптери та інтеграції
│   │   ├── db/              # Підключення до БД та миграції
│   │   ├── middleware/      # Middleware для обробки HTTP-запитів
│   │   ├── modules/         # Бізнес-модулі системи
│   │   ├── routes/          # Маршрути API (эндпоінти)
│   │   ├── types/           # Опис типів TypeScript
│   │   ├── app.ts           # Конфігурація додатка
│   │   └── server.ts        # Точка входу / запуск сервера
│   ├── package.json
│   └── tsconfig.json
├── docs/                    # Проєктна документація та специфікації
│   └── .gitkeep
├── frontend/                # Клієнтська частина додатка (React + Vite)
│   ├── src/
│   │   ├── components/      # UI-компоненти React
│   │   ├── services/        # Сервіси для роботи з API backend'у
│   │   ├── types/           # Типи та інтерфейси frontend
│   │   ├── App.tsx          # Головний компонент додатка
│   │   ├── index.css        # Глобальні стилі
│   │   └── main.tsx         # Точка входу React
│   ├── index.html
│   ├── package.json
│   ├── tsconfig.json
│   └── vite.config.ts
├── tests/                   # Набір авто-тестів (unit/integration)
├── .gitignore               # Виключення Git для всього репозиторію
├── .prettierrc              # Конфігурація форматирування Prettier
├── eslint.config.js         # Конфігурація лінтера ESLint
├── package.json             # Корневий package.json для загальних скриптів
└── README.md                # Головна документація проєкту
```

## Інструкція із запуску проєкту

### Передумови
* Node.js (версія 18 або вище)
* npm або pnpm
* PostgreSQL (для роботи бази даних бекенду)

### Кроки для локального розгортання:

1. **Клонування репозиторію:**

```Bash
git clone [https://github.com/your-username/SDLC.git](https://github.com/your-username/SDLC.git)
cd SDLC
```

2. Підтягування всіх актуальних гілок та оновлень:

```Bash
git fetch --all --prune
```

3. Встановлення залежностей (у корені, бекенді та фронтенді):

```Bash
# Залежності кореня (включно з Husky)
npm install

# Встановлення залежностей бекенду
cd backend && npm install

# Встановлення залежностей фронтенду
cd ../frontend && npm install
cd ..
```

4. Запуск серверної частини (Backend):

```Bash
cd backend
npm run dev
```

5. Запуск клієнтської частини (Frontend):

```Bash
cd frontend
npm run dev
```

6.Запуск тестів:

```Bash
npm run test
```
