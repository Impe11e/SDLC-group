# Інтернет-магазин спортивного харчування

Веб-платформа для продажу спортивного харчування, добавок та суміжних товарів: каталог із пошуком і фільтрацією, кошик, оформлення замовлень та особистий кабінет користувача.

---

## Технологічний стек

| Шар                 | Технології                                     |
| :------------------ | :--------------------------------------------- |
| **Backend**         | Node.js 22, TypeScript 6, Express 5, pg        |
| **Frontend**        | React 19, React Router 7, Vite 8, TypeScript 6 |
| **База даних**      | PostgreSQL 16                                  |
| **Тестування**      | Vitest (unit-тести сервісів)                   |
| **Якість коду**     | ESLint 10, Prettier, Husky + lint-staged       |
| **Контроль версій** | Git, GitHub, Pull Requests                     |
| **CI**              | GitHub Actions (lint, build, test на кожен PR) |

## Структура проєкту

Архітектура: **модульний моноліт**. Один Express-застосунок, поділений на модулі, працює з однією БД PostgreSQL. React-клієнт звертається до нього через REST API.

## Інструкція із запуску інтегрованої системи

### Передумови

- **Node.js 22.13+** (версія зафіксована в `.nvmrc`, тож достатньо виконати `nvm use`)
- **Docker** з Docker Compose (для PostgreSQL)
- Git

### Кроки

1. **Клонування репозиторію:**

    ```bash
    git clone https://github.com/Impe11e/SDLC-group.git
    cd SDLC-group
    nvm use            # необов'язково, якщо Node 22 вже встановлено
    ```

2. **Встановлення залежностей** (одна команда в корені ставить залежності бекенду й фронтенду, бо проєкт використовує npm workspaces):

    ```bash
    npm ci             # строго за package-lock.json (рекомендовано)
    # або npm install - якщо додаєте/оновлюєте залежності
    ```

3. **Запуск бази даних:**

    ```bash
    npm run db:up
    ```

    При першому запуску контейнер сам виконує всі файли `backend/db/01…06_*.sql`. Якщо БД було створено раніше (до появи нових файлів), найпростіше створити її заново (дані локальної БД буде втрачено):

    ```bash
    docker compose down -v
    npm run db:up
    ```

    Або застосувати лише новий файл, не чіпаючи дані (працює і в PowerShell):

    ```bash
    docker cp backend/db/06_reviews.sql sdlc-postgres:/tmp/06_reviews.sql
    docker compose exec -T db psql -v ON_ERROR_STOP=1 -U shop -d shop -f /tmp/06_reviews.sql
    ```

4. **Змінні оточення бекенду:**

    ```bash
    cp backend/.env.example backend/.env
    ```

    Значення БД за замовчуванням збігаються з `docker-compose.yml`. Додатково: `JWT_SECRET` (секрет для підпису токенів) і `APP_URL` (адреса фронтенду для посилань відновлення пароля, локально `http://localhost:5173`).

    Щоб отримати роль адміністратора (FR-7), після реєстрації виконайте і увійдіть знову:

    ```bash
    docker compose exec db psql -U shop -d shop -c "update users set role='ADMIN' where nickname='ВАШ_НІКНЕЙМ';"
    ```

5. **Запуск бекенду** (http://localhost:3000):

    ```bash
    npm run dev:backend
    ```

    У консолі має з'явитися `Connected to PostgreSQL`.

6. **Запуск фронтенду** (в окремому терміналі, http://localhost:5173):

    ```bash
    npm run dev:frontend
    ```

7. **Тести та збірка** (з кореня):

    ```bash
    npm test           # unit-тести бекенду (Vitest)
    npm run build      # збірка бекенду і фронтенду
    npm run lint       # ESLint бекенду і фронтенду
    ```

8. **Зупинка БД:** `npm run db:down`. Дані зберігаються у volume `pgdata`. Щоб повністю скинути БД і заново застосувати схему та seed, виконайте `docker compose down -v`.

Лист для відновлення пароля поки не надсилається поштою: Email Adapter виводить посилання в консоль бекенду (рядок `[email] ...`).

## Відомі обмеження та подальші кроки

- Лист для відновлення пароля поки не надсилається поштою: `ConsoleEmailAdapter` виводить посилання в логи. Для реальної відправки достатньо додати адаптер з інтерфейсом `IEmailSender` (наприклад, на SMTP) без змін у сервісі.
- Роль адміністратора видається вручну через SQL (окремого інтерфейсу керування користувачами немає).
- Безкоштовна БД Render діє 30 днів (див. розділ «Деплой»).
- Моніторинг доступності (NFR Reliability, SCRUM-32) ще не налаштовано.
- Відхилення від діаграми класів ЛР2, прийняті свідомо: `cart_items` прив'язані напряму до `user_id` (без окремої таблиці `carts`), поле залишку називається `stock`, поле фото називається `image_url`, у `orders` додано поле `status` (за замовчуванням `NEW`) для майбутнього адмін-функціоналу.
