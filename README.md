# Інтернет-магазин спортивного харчування

Веб-платформа для продажу спортивного харчування, добавок та суміжних товарів: каталог із пошуком і фільтрацією, кошик, оформлення замовлень та особистий кабінет користувача.

---

## Технологічний стек

| Шар                 | Технології                                     |
| :------------------ | :--------------------------------------------- |
| **Backend**         | Node.js 22, TypeScript 6, Express 5, pg        |
| **Frontend**        | React 19, React Router 7, Vite 8, TypeScript 6 |
| **База даних**      | PostgreSQL 16                                  |
| **Тестування**      | Vitest (unit-тести сервісів)                   |
| **Якість коду**     | ESLint 10, Prettier, Husky + lint-staged       |
| **Контроль версій** | Git, GitHub, Pull Requests                     |

## Структура проєкту

Архітектура: **модульний моноліт**. Один Express-застосунок, поділений на модулі, працює з однією БД PostgreSQL. React-клієнт звертається до нього через REST API.

```text

├── backend/                     # Серверна частина (Node.js / TypeScript / Express)
│   ├── db/

│   │   └── 02_seed.sql          # Тестові товари

│   │   ├── adapters/            # Зовнішні адаптери (Email Adapter для FR-10)
│   │   ├── db/pool.ts           # Єдиний DB Connection Pool

│   │   ├── middleware/          # Auth Middleware, user-context (тимчасовий)
│   │   ├── modules/             # Бізнес-модулі: Router → Schema → Service → Repository
│   │   │   ├── auth/            # Реєстрація та вхід (FR-1)
│   │   │   ├── user/            # Профіль (FR-9)

│   │   └── server.ts            # Точка входу

├── frontend/                    # Клієнтська частина (React + Vite)
```

## Інструкція із запуску інтегрованої системи

### Передумови

- **Node.js 22.13+** (версія зафіксована в `.nvmrc`, тож достатньо виконати `nvm use`)
- **Docker** з Docker Compose (для PostgreSQL)
- Git

### Кроки

1. **Клонування репозиторію:**

    ```bash
    git clone https://github.com/Impe11e/SDLC-group.git
    cd SDLC-group
    nvm use            # необов'язково, якщо Node 22 вже встановлено
    ```

2. **Встановлення залежностей** (одна команда в корені ставить залежності бекенду й фронтенду, бо проєкт використовує npm workspaces):

    ```bash
    npm ci             # строго за package-lock.json (рекомендовано)
    # або npm install - якщо додаєте/оновлюєте залежності
    ```

3. **Запуск бази даних:**

    ```bash
    npm run db:up
    ```

4. **Змінні оточення бекенду** (необов'язково: значення за замовчуванням збігаються з `docker-compose.yml`):

    ```bash
    cp backend/.env.example backend/.env
    ```

5. **Запуск бекенду** (http://localhost:3000):

    ```bash
    npm run dev:backend
    ```

    У консолі має з'явитися `Connected to PostgreSQL`.

6. **Запуск фронтенду** (в окремому терміналі, http://localhost:5173):

    ```bash
    npm run dev:frontend
    ```

7. **Тести та збірка** (з кореня):

    ```bash
    npm test           # unit-тести бекенду (Vitest)
    npm run build      # збірка бекенду і фронтенду
    npm run lint       # ESLint бекенду і фронтенду
    ```

8. **Зупинка БД:** `npm run db:down`. Дані зберігаються у volume `pgdata`. Щоб повністю скинути БД і заново застосувати схему та seed, виконайте `docker compose down -v`.

### Основні ендпоінти API

| Метод            | Шлях                             | Опис                                                               |
| :--------------- | :------------------------------- | :----------------------------------------------------------------- |
| `POST`           | `/api/auth/register`             | Реєстрація (нікнейм, email, пароль)                                |
| `POST`           | `/api/auth/login`                | Вхід, повертає токен                                               |
| `GET` / `PATCH`  | `/api/users/:id`                 | Перегляд / зміна імені профілю                                     |
| `GET`            | `/api/products`                  | Список товарів                                                     |
| `GET`            | `/api/products/:id`              | Картка товару                                                      |
| `GET` / `DELETE` | `/api/cart`                      | Вміст кошика / очищення                                            |
| `POST`           | `/api/cart`                      | Додати товар `{ productId, quantity }`                             |
| `PUT` / `DELETE` | `/api/cart/:productId`           | Змінити кількість / видалити позицію                               |
| `POST`           | `/api/orders`                    | Оформити замовлення `{ fullName, deliveryAddress, paymentMethod }` |
| `GET`            | `/api/orders`, `/api/orders/:id` | Історія замовлень / деталі                                         |

## Відомі обмеження та подальші кроки

- **Авторизація (у процесі, `feature/auth-jwt`):** таблиця `users` у PostgreSQL, bcrypt, справжній JWT, `authMiddleware` замість тимчасового `user-context` на `/cart` та `/orders`, вхід за нікнеймом або email, підключення сторінки профілю. Доки цю роботу не завершено, кошик спільний для всіх користувачів (`userId = 1`).
- Відхилення від діаграми класів ЛР2, прийняті свідомо: `cart_items` прив'язані напряму до `user_id` (без окремої таблиці `carts`), поле залишку називається `stock`, у `orders` додано поле `status` (за замовчуванням `NEW`) для майбутнього адмін-функціоналу.
- Не реалізовано: FR-7 (адмін-панель), FR-8 (відгуки), FR-10 (відновлення пароля), деплой на Render з HTTPS.
